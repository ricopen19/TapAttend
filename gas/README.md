# TapAttend GAS デプロイ手順

## ファイル

- `Code.gs`: バックエンド（スプレッドシート読み書き）。ソース。
- `appsscript.json`: マニフェスト。ソース。
- `index.html`: `npm run build:gas` の出力。**このファイルは編集しない**（次回ビルドで上書きされる）。

## 初回セットアップ

1. `npm run build:gas` を実行し、`gas/index.html` を生成する
2. https://script.google.com/ で新規プロジェクト作成
3. `Code.gs` の中身を `gas/Code.gs` の内容で置き換える
4. 左の「+」→「HTML」でファイル追加、ファイル名を `index`（拡張子なし）にして `gas/index.html` の内容を貼り付ける
5. 一度どれかのGAS関数（`listClasses` など）を実行するか、Webアプリとして開いて出欠データスプレッドシート（「TapAttend出欠データ」）を自動生成させる
6. 出欠データスプレッドシートの「設定」タブを開き、学年番号（クラス作成時に入力する「学年組」の先頭の数字と一致させる）と、対応する名簿マスタのスプレッドシートIDを1行ずつ入力する
   | 学年 | スプレッドシートID |
   |---|---|
   | 1 | 1学年の名簿マスタのスプレッドシートID |
   | 2 | 2学年の名簿マスタのスプレッドシートID |

   年度更新で名簿マスタが変わった際も、このタブのセルを書き換えるだけでよい（GASエディタの操作は不要）。
7. 「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」
   - 次のユーザーとして実行: 自分
   - アクセスできるユーザー: 組織内
8. 発行された `/exec` URL を教員に共有する

## コード更新時

1. `npm run copy:gas` を実行する（ビルド→`Code.gs`をコピー→貼り付け待ち→`index.html`をコピー→貼り付け待ち、の順に案内される）
2. 表示に従って、GASエディタの `Code.gs` と `index` に貼り付ける（クリップボードは1つしかないので、案内された順番を飛ばさないこと）
3. 「デプロイ」→「デプロイを管理」→ 既存デプロイの鉛筆アイコンから「新しいバージョン」を選んで更新（URLは変わらない）

⚠️ エディタで開きっぱなしのタブから手動でコピーしないこと。このリポジトリは外部ボリューム上にあり、エディタのファイル監視が変更を拾い損ねて古い内容のままコピーしてしまうことがある（実際に発生した）。`npm run copy:gas` は毎回ディスクを直接読むターミナル経由なので安全。

## 出欠データスプレッドシートについて

司令塔となる「TapAttend出欠データ」（クラス一覧・設定タブ）は初回アクセス時に自動作成され、そのIDはスクリプトプロパティに保存される。
手動で作る必要はない。「設定」タブも自動作成されるが、中身（学年とスプレッドシートIDの対応）は手動入力が必要。

学年組ごとの実データ（`${年度}_${学年組}_出欠席データ`）は、クラスを初めて作成したタイミングで
Driveの「TapAttend出欠データ」フォルダ配下に自動作成される。このフォルダもスクリプトプロパティにIDが保存され、
手動で作る必要はない。

Driveへのファイル作成・フォルダ操作が新たに必要になったため、コード更新後に初めてクラス作成を実行する際、
GASから改めて権限承認を求められることがある（画面の指示に従って許可すればよい）。
